Problem

AI agents are starting to pay for work.
But an LLM answers in prose.

ASK AN LLM: "RELEASE THE ESCROW?"

"I reviewed this request. The report appears to have been delivered and the payer seems to have approved it. That said, the scope of the approval is not fully clear… releasing the funds is probably fine, but to be safe…"

WHY IT FAILS
  • A program can't act on "probably fine".
  • Nobody can check who decided, or how sure.
  • Waiting ~12.8 s for finality breaks the flow.
Solution

A typed decision the chain can verify — and settle in under a second.

On-chain program

Four instructions, one rule.

Instruction What it does
deposit Payer locks SOL in the escrow PDA, with a deadline and a hash of the request
settle Checks the oracle-signed decision; pays the payee only if release and probability ≥ 7000 bps
refund After a signed refund ≥ 70%, or once the deadline passes — funds return to the payer
close Closes a finished escrow and returns the rent to the payer 
let release = decision == DECISION_RELEASE && probability_bps >= RELEASE_THRESHOLD_BPS; // 7000
Signed decisions

The program reads the Ed25519 instruction right before settle.

// 88-byte message the oracle signs
"sokketsu-decision-v3"  20 bytes
escrow pubkey           32
sha256(request)         32
decision                 1  release·hold·refund
probability_bps          2
source                   1  jev · mock
// verify_oracle_decision
prev = instruction[current - 1]
require prev.program == ed25519_program
require pubkey  == ORACLE_PUBKEY
require message == decision_message(
  escrow, state_hash,
  decision, bps, source)
// else BadOracleSignature

Binding the escrow and the request hash means a signature can't be re-used for another escrow or a different request.
